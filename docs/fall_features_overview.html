Feature 1

Fall alert

Caregivers see a fall as it happens, on wherever they are inside the dashboard.

Möglicher Sturz, warte auf Bestätigung
A fall was detected. The patient is being asked on the phone.
Sturz bestätigtHilfe angefordert
The patient needs help or doesn't answer. This stays on screen until a caregiver acknowledges it.
Patient:in meldet keinen Sturz
The patient says it wasn't a fall. This disappears after 8 seconds.

Where it shows: on every page, including on top of open dialogs. The patient's bar on the overview changes colour too, and an indicator in the header shows whether alerts can arrive.

Feature 2

Fall history

Caregivers see how often a patient has fallen.

Example values

Overview: Stürze (7 Tage)2
Patient page: Stürze on the selected day1
14:32:10BestätigtHilfe: Ja
  • Overview: each patient's falls in the last 7 days.
  • Patient page: falls on the date chosen in the calendar, with a list showing the time, the patient's answer and whether help was requested.

What counts: every fall, unless the patient said it wasn't one. No answer still counts, because the patient may have been unable to answer.

System Architecture (Simplified)

  • Fall alert: arrives live through the message broker
  • Fall history: read from the database

Next steps for you (FOKUS)

Technical person at FOKUS: six steps

Full details are in README.md on the branch.

  1. Get the code

    Pull the source code from branch fall-dashboard-integration (pushed last week) and check for conflicts.

  2. Fill in the credentials

    Copy dart_defines.example.json to dart_defines.local.json, then add the URL and token for InfluxDB and the username and password for the MQTT broker. The credentials will be sent separately.

  3. Build the webapp 
    flutter build web --release --dart-define-from-file=dart_defines.local.json
    or for local testing, 
    flutter run -d chrome --web-port 8080 --dart-define-from-file=dart_defines.local.json --web-browser-flag "--disable-web-security"

    The last flag is only needed locally. localhost is a different origin from the FHIR server, which rejects the serviceaccesstoken header from there (CORS), so without the flag the patient list stays empty. It only affects the temporary Chrome window Flutter opens. Never use it for anything except local development.

  4. Deploy it as today
  5. Allow the connection to the broker

    The Patient Dashboard Webapp needs outgoing WSS on port 443 to fall-mqtt.smarko-health.de.

  6. Check it and tell MCS

    The header shows "Sturzalarm verbunden", and "Stürze (7 Tage)" shows numbers. MCS then confirms the connection on the broker.
